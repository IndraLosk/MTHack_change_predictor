# MTHack_change_predictor

Комплексное решение для хакатона Московского транспорта: **ИИ-предиктор изменений в графике
движения городского транспорта**. Система непрерывно принимает потоковую телеметрию **NDTP**,
сопоставляет её с эталонным расписанием, **ML-моделью прогнозирует задержки за 10–15 минут** до
события и выводит алерты на **диспетчерский BI-дашборд**.

---

## Что делает система

- Непрерывно принимает и парсит потоковые телеметрические пакеты **NDTP** (от эмулятора по TCP).
- Накопливает телеметрию в PostgreSQL (`ndtp_telemetry`) и CSV (запасной контур).
- Сопоставляет с расписанием и считает производные признаки: текущее отклонение от графика,
  среднюю скорость на сегменте, долю простоя, позицию на маршруте.
- Предсказывает задержку на следующей плановой остановке в окне **T+10…15 мин**
  (LightGBM по 24 признакам, только на данных, доступных на момент T — без утечки).
- Формирует **живые ранние оповещения** (live-алерты) и офлайн-прогнозы по валидационным точкам —
  всё пишется в таблицу `predictions`.
- Отдаёт результат через **HTTP API** (Swagger на `/docs`) и **BI-дашборд Grafana** с картой
  города, цветовой индикацией риска и журналом алертов.

---

## Архитектура

Решение из **5 контейнеров** (Docker Compose), с чётким разделением Backend (API/оркестрация)
и ML-ядра (инференс):

| Сервис | Роль | Порт |
|---|---|---|
| `ndtp-emu` | Эмулятор телеметрии NDTP (шлёт пакеты по TCP) | 18080 (REST) |
| `db` | PostgreSQL 16 — единое хранилище телеметрии, расписания, прогнозов | 5433 |
| `backend` | FastAPI: TCP-приёмник NDTP :9201, парсинг, признаки, API | 8000 |
| `ml-model` | LightGBM-инференс: офлайн-точки + live-алерты, Map Matching | — |
| `grafana` | BI-дашборд (карта, алерты, статы) + Unified Alerting | 3000 |

Связи: `ndtp-emu` → TCP:9201 → `backend` → `db`; `ml-model` ↔ `db`; `grafana` → `db`;
наружу данные отдаются через `backend` (HTTP) и напрямую из PostgreSQL через Grafana.

Строка подключения к БД: `postgresql://mthack:mthack@localhost:5433/mthack`

## Стек

Python 3.12, FastAPI, Uvicorn, asyncpg, LightGBM, pandas, numpy, PostgreSQL 16, Docker Compose, Grafana.
ML и Backend упакованы в отдельные контейнеры, сборка по одной команде.

## Запуск (одна команда)

Требования: **Docker Desktop** (Windows/Mac) или Docker Engine + Compose (Linux); ~5 ГБ места;
для Grafana — доступ к Docker Hub (скачивается образ `grafana/grafana:13.2.2`).

### Шаг 1. Датасет

Положите файлы в `dataset/` (см. структуру ниже). Если чего-то нет — скачайте полный набор:
> https://disk.yandex.ru/d/CA6tsj4aJJ4Aaw (актуальная ссылка из ТЗ)

### Шаг 2. Setup (один раз)

```bash
make setup
```
Загружает образ эмулятора из локального `dataset/ndtp-telemetry-emulator.tar` и скачивает Grafana
из Docker Hub (идемпотентно: пропускает, если образы уже есть).

### Шаг 3. Поднять всё

```bash
make up
```
Поднимает **все 5 сервисов** (эмулятор, БД, backend, ml-model, Grafana). Первый прогноз появляется
через ~20–60 секунд.

### Шаг 4. Проверить

```bash
make health      # → {"status":"ok"}
make ps          # все 5 контейнеров в статусе Up
```

После старта:
- **API + Swagger:** http://localhost:8000/docs
- **BI-дашборд Grafana 13:** http://localhost:3000 (admin / admin) → «Диспетчерская 2 + 1 = 21»
- **Эмулятор NDTP:** http://localhost:18080

## BI-дашборд Grafana

Провижинится автоматически из `grafana/` при `make up`:
- **Live-мониторинг** (Geomap): автобусы на карте, цвет по скорости (тёмно-красный <15, жёлтый <40,
  зелёный >40), треки за 30 мин (линии), центр Москва. Автообновление 5 с.
- **ML-прогноз: Топ критических задержек** — таблица прогнозов по убыванию (красные при >80 с).
- **Активные ТС на маршрутах** — gauge.
- **Журнал инцидентов** — список сработавших алертов.
- **Среднее отклонение от расписания** — стат (сек).
- **Unified Alerting**: правило алерта на пиковую прогнозируемую задержку > 120 с (видно в
  колокольчике справа сверху и в панели «Журнал инцидентов»).

Все панели читают общую БД PostgreSQL напрямую (`localhost:5433 / mthack`).
Datasource для дашборда провижинится автоматически (uid `dfzjcy11ify0wa`).

> Базовая подложка карты (тайлы 2ГИС) требует доступ к тайл-серверу с машины, где открыт дашборд — если
> карта кажется пустой, переключите подложку на OSM/Яндекс (одна правка `basemap` в
> `grafana/dashboards/transport.json`).

> Если `make up` упал на pull Grafana с `error getting credentials` — это проблема доступа к
> Docker Hub на машине (сломан `credsStore`), а не системы. Решение: убрать `"credsStore"`
> из `~/.docker/config.json` и перезапустить Docker Desktop, либо выполнить `make setup`.

## ML-модуль

- **Модель:** LightGBM (`regression_l1`), `ml-model/model.txt` (совместим с новым `features.py`).
- **Признаки** (`features.py`, 24 шт.): горизонт прогноза, время/день недели, время с последнего
  пакета, скорость/координаты, статистика скорости за 5/10 мин, пройденное расстояние, плановый
  интервал, дистанция до целевой остановки, ETA-задержки, текущее отклонение `cur_dev_s`. Только
  данные на момент T — исключение утечки будущего.
- **Задачи инференса:** офлайн по `forecast_points` (validate) + live `live_early_warning()` для
  активных ТС в окне **T+10…15 мин**. Прогноз подписан: `+` = опоздание, `−` = опережение (сек).
- **Map Matching** (`map_matching.py`): привязка GPS-позиций к нити маршрута с учётом курса/скорости.

---

## Производительность и надёжность

- **Latency** инференса логируется (`[live] ... latency=NN.Nms`) — ориентир < 1–2 с на поток наружен.
- **Без накопления очередей:** `GET /api/queue/status` (`csv_queue_size ≈ 0`, `csv_dropped = 0`).
- **Деградация:** при недоступной модели сервис не падает (`ready=False`); при «молчащем» потоке
  >45 с прогнозы помечаются `stale` и строятся по последним данным; TCP-приёмник переживает reconnect.
- **Холодный старт:** весь стек — одной командой `make up`.
